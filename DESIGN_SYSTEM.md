# Дизайн-система веб-панели

Этот файл описывает, как устроен интерфейс панели после редизайна: какие
есть токены и компоненты, по каким правилам собирается новая страница и
какие есть подводные камни. Продуктовые решения — в
[PROJECT_SPEC.md](PROJECT_SPEC.md), история реализации — в
[SESSION_CONTEXT.md](SESSION_CONTEXT.md).

Первый раздел — что конкретно изменилось относительно первоначальной
версии панели. Всё остальное — правила, которым нужно следовать, добавляя
новые страницы, иначе дизайн расползётся.

---

## 1. Что было сделано

Отправная точка: панель работала, но выглядела как черновик — 100 строк CSS
с несколькими переменными, верхнее меню, голые таблицы, длинные формы без
группировки. Задача была довести до уровня нормального SaaS-дашборда, не
меняя стек: FastAPI + Jinja2, серверный рендеринг, обычные POST + redirect,
без React/сборщиков/Node.

### Файлы

| Файл | Что с ним |
|---|---|
| `app/web/static/style.css` | Переписан целиком: 100 → ~1125 строк, полноценная дизайн-система |
| `app/web/templates/base.html` | Новый каркас: верхнее меню → боковая панель, flash → компонент `.alert` |
| `app/web/templates/_macros.html` | **Новый файл** — общие макросы и русские подписи статусов |
| `app/web/templates/dashboard.html` | Переписан: метрики, график активности, состояние флота |
| `app/web/templates/accounts.html` | Переписан: форма в `<details>`, плотная таблица, панель массовых действий |
| `app/web/templates/account_detail.html` | Переписан: двухколоночная раскладка, `confirm()` на опасных действиях |
| `app/web/templates/channels.html` | Переписан |
| `app/web/templates/personas.html` | Переписан: каждая персона — сворачиваемая карточка |
| `app/web/templates/settings.html` | Переписан: липкая панель сохранения |
| `app/web/templates/logs.html` | Переписан: фильтры, нормальная пагинация |
| `app/web/routes/dashboard.py` | Новые запросы под дашборд (см. ниже) |
| `app/web/routes/logs.py` | Фильтры + корректная пагинация (см. ниже) |

Модели, worker, сервисы, миграции — **не трогались**. Изменения в двух
роутах — единственное, что вышло за пределы вёрстки.

### Что изменилось в роутах

**`routes/dashboard.py`** — старый дашборд показывал четыре числа, для
наглядности нужны были данные:

- `failed_today`, `scheduled_pending` — счётчики для карточек-метрик;
- `all_channels` — чтобы показывать «4 активных / 5 всего»;
- ряд публикаций по дням за 14 дней (`ACTIVITY_DAYS`) через
  `func.date(CommentLog.posted_at)` + `GROUP BY` — это единственный новый
  SQL в проекте. Драйвер может вернуть `date` или строку `'YYYY-MM-DD'`,
  поэтому ключи нормализуются перед сборкой ряда;
- в выборку `recent` добавлен `joinedload(account)` / `joinedload(channel)`
  — шаблон теперь показывает названия, а не голые id.

**`routes/logs.py`**:

- фильтры `status` и `channel_id` из GET-формы; неизвестный статус молча
  сбрасывается в «все», а не роняет запрос;
- `COUNT(*)` → `total` / `total_pages`, номер страницы зажимается в
  границы. Раньше кнопка «Вперёд» показывалась всегда, в том числе на
  последней странице, и уводила на пустой список;
- `joinedload` на `account` / `channel` (раньше уже был).

### Как проверялось

Все семь шаблонов прогонялись через Jinja офлайн, с моковыми данными —
ловились синтаксические ошибки шаблонов и ошибки в именах переменных.
Дополнительно проверено, что в шаблонах не осталось ссылок на удалённые
классы и нет кнопок без класса `.btn`.

**Не проверялось: живой запуск на реальной БД.** Postgres не поднимался,
пустая база на превью всё равно ничего бы не показала. Первое, что стоит
сделать — `docker compose up` и посмотреть дашборд на настоящих данных:
запрос активности с `func.date` + `GROUP BY` — единственное место, которое
на реальном Postgres может повести себя не так, как на моках.

## 2. Токены

Всё живёт в `:root` в начале `style.css`. Хардкодить цвета в шаблонах не
нужно — если чего-то не хватает, добавляется токен.

**Нейтральная шкала** — холодный графит, три уровня поверхностей и три
уровня границ. Три уровня нужны, чтобы карточка, инпут внутри неё и
hover-состояние строки не сливались:
`--c-bg` → `--c-surface` → `--c-surface-2` → `--c-surface-3`,
`--c-line-soft` → `--c-line` → `--c-line-hard`.

**Текст** — `--c-text` (основной), `--c-text-2` (вторичный),
`--c-text-3` (подписи, плейсхолдеры, приглушённое).

**Акцент** — индиго-фиолет `--c-brand` (`#6c7cff`). Не синий: синий занят
информационным статусом (`scheduled`), и в таблице акцентная ссылка с ним
путалась.

**Семантика статусов** — `--c-ok` / `--c-warn` / `--c-bad` / `--c-off` и их
`-soft` варианты для фонов. **Эти цвета используются только для статусов.**
Если понадобился зелёный «просто чтобы было красиво» — это ошибка.

**Шрифты** — `--font-ui` (системный стек, на Windows это Segoe UI Variable:
хорошая кириллица, ноль сетевых запросов) и `--font-mono` для технических
значений. Вебшрифтов нет и не должно быть — их некуда подключать без
сборщика, а CDN добавит внешнюю зависимость.

Тема только тёмная. Это осознанно: инструмент рабочий, светлой темы в
требованиях не было, поддержка двух тем удвоила бы объём CSS.

## 3. Каркас страницы

`base.html` даёт сайдбар (246px, sticky, с группами «Мониторинг /
Управление / Система») и sticky-топбар. Ниже 1000px сайдбар складывается в
горизонтальную ленту.

Скелет новой страницы:

```jinja
{% extends "base.html" %}
{% from "_macros.html" import account_status, empty_row %}

{% block title %}Название — Diablogram AI{% endblock %}
{% block page_title %}Название{% endblock %}
{% block page_sub %}<div class="topbar__sub">Одна строка контекста</div>{% endblock %}
{% block page_actions %}<a href="/..." class="btn btn-sm">Действие</a>{% endblock %}

{% block content %}
  ...
{% endblock %}
```

`<h1>` внутри `content` не нужен — заголовок отдаёт `page_title`.

Чтобы пункт меню подсвечивался, роут должен передавать `active` с одним из
значений: `dashboard`, `channels`, `accounts`, `personas`, `settings`,
`logs`. Иконки навигации — макрос `icon()` в самом `base.html`.

## 4. Компоненты

**Карточка** — `.card` с `.card__head` / `.card__body` / `.card__foot`.
Для таблицы внутри карточки — `.card__body.is-flush` (убирает паддинг),
таблица всегда обёрнута в `.table-wrap` (горизонтальный скролл).

**Сворачиваемая карточка** — `<details class="card">` с разметкой
`.summary__icon` / `.summary__title` / `.summary__desc` /
`.summary__chevron`. Используется для форм добавления: так таблица с
данными оказывается на первом экране, а не третьим блоком. Открыта по
умолчанию, когда список пуст: `{{ 'open' if not items }}`.

**Таблица** — `table.data`, обязательно с `<thead>` и `<tbody>` (шапка
sticky и завязана на `thead`). Модификаторы ячеек: `.col-num` (числа,
выравнивание вправо, `tabular-nums`), `.col-tight` (не переносить,
минимальная ширина), `.col-text` (длинный текст, приглушённый),
`.col-actions` (кнопки справа). Двухэтажная ячейка — `.cell-title` +
`.cell-sub`. Пустая таблица — макрос `empty_row(cols, text)`.

**Бейджи статусов** — `.badge` + класс, **равный значению енума**:
`active` / `limited` / `banned` / `disabled`,
`posted` / `scheduled` / `failed` / `skipped_filter`. Русские подписи — в
`_macros.html`, макросы `account_status(value)` и `comment_status(value)`.
Не пишите подписи руками в шаблонах: словари `ACCOUNT_STATUS_LABELS` и
`COMMENT_STATUS_LABELS` — единственный источник правды, оттуда же берётся
выпадающий фильтр в журнале.

**Кнопки** — всегда `.btn` плюс вариант: `.btn-primary` (основное
действие, одно на форму), `.btn-danger` (разрушительное), `.btn-ghost`
(третьестепенное), `.btn-sm` (в таблицах и тулбарах). Голый `<button>` без
класса **не стилизован** — это намеренно, чтобы такое сразу бросалось в
глаза.

**Формы** — поле это `.field` (label + контрол + `.field__hint`), ряд полей
`.field-grid` (или `.cols-2` / `.cols-3`), логический раздел длинной формы
— `<fieldset class="fieldset">` с `.fieldset__legend`. Чекбоксы и радио
перерисованы через `appearance: none`, включая `:indeterminate`. Для
акцентного переключателя есть `.check-card`, для сетки чекбоксов —
`.check-grid`.

**Метрики и графики** — `.stat` (с тональностями `.tone-ok` / `.tone-warn`
/ `.tone-bad` / `.tone-off`), `.meter` + `.legend` (составная полоса),
`.chart` (столбчатый график). Всё на чистом CSS, высота столбца задаётся
инлайновой переменной `--h`, подсказка — нативным `title`. Никаких
библиотек графиков.

**Прочее** — `.alert` (варианты `.is-ok` / `.is-warn` / `.is-bad`),
`.empty` (пустое состояние), `.pager`, `.kv` (список «ключ — значение»),
`.chip` (технические значения: хост, `@username`, id), `.count-pill`,
`.form-actions` (липкая панель сохранения).

## 5. Правила

- **Никакого шага сборки и никакого JS-фреймворка.** Весь JS в проекте — это
  один `<script>` в `accounts.html` («выбрать все» с поддержкой
  `indeterminate` и счётчиком отмеченных) плюс инлайновые `confirm()` в
  атрибутах `onsubmit` / `onclick` в `account_detail.html` и
  `personas.html`. Если задача требует больше — сначала подумать, решается
  ли она на CSS.
- **`joinedload` обязателен**, если шаблон обращается к связанной модели
  (`log.channel`, `log.account`, `ban.channel`). Сессия закрывается до
  рендера, ленивая подгрузка падает с `MissingGreenlet`. На этом проект уже
  спотыкался — см. коммит `0028ae8`.
- **Новый статус в енуме → нужен CSS-класс** и строка в словаре подписей в
  `_macros.html`. Без класса бейдж отрендерится нейтрально-серым: не
  сломается, но потеряет смысл.
- **Моноширинный шрифт для технических значений** — id, хосты, порты,
  session-строки, время, тексты ошибок. Цифры в колонках —
  `font-variant-numeric: tabular-nums` (уже в `.col-num`, `.num`, `.mono`).
- **`confirm()` на разрушительном** — удаление персоны, приостановка
  аккаунта, замена session-строки.
- **Цвет несёт смысл.** Акцент — для интерактивного, семантические цвета —
  для статусов. Всё остальное — нейтральная шкала.

### Подводные камни

- В `<textarea>` значение должно начинаться сразу после `>`, без перевода
  строки — иначе браузер съест первую строку. Актуально для стоп-слов в
  настройках.
- `{{ list | join('\n') }}` в Jinja работает как ожидается: Jinja
  обрабатывает escape-последовательности в строковых литералах, `'\n'` —
  настоящий перевод строки, а не два символа.
- `.truncate` внутри flex-контейнера требует `min-width: 0` на
  родителе — для `<summary>` это уже прописано в CSS, в новых местах нужно
  помнить.
